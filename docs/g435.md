# Logitech G435 LIGHTSPEED receivers

The G435 does **not** speak HID++. The two dongles use different transports and different drivers.

| Receiver | USB ID | Driver | Bridge |
|---|---|---|---|
| Original Realtek | `046D:0ACB` | `src/drivers/g435.cpp` | Realtek PA / bootloader, usage page `FFC0`, feature report 6 (64 bytes) |
| Newer Holtek | `046D:0ADF` | `src/drivers/logitech_g435_0adf.cpp` | CRC-16 framed vendor reports, `GET_BATTERY` in mV |

The `0ADF` driver reads on every poll. A read does not mute audio. The rest of this note is the `0ACB` path.

## Realtek (`0ACB`)

Battery is only available through the dongle's vendor bridge, and each read mutes USB audio for about a second. A successful reading is kept in memory for 45 minutes. After a failed read (headset off or not linked) the previous value stays visible as asleep and the driver retries after 5 minutes. *Refresh now* reads immediately. Nothing is written to flash or the registry.

Enter, PA, and exit are `HidD_SetFeature` on report 6 (padded to 64 bytes), the same transport as [fr0styJS/g435-lightspeed-battery](https://github.com/fr0styJS/g435-lightspeed-battery) and WirelessBattery PR #93. The battery reply is `HidD_GetFeature` on that same report.

1. Enter bootloader (`06 01 03`) — mutes USB audio while open
2. Remote mode (`06 04 03 00 <len>` + `PA 0E E1 01`) so OTA commands reach the headset
3. OTA get battery (`PA 06 00 31`) → reply contains `06 80 00 <mV LE16>`
4. Local mode (`PA 0E E1 00`)
5. Exit bootloader (`06 08 03`) — always runs after a successful enter

Without remote mode the dongle answers with its own junk value (~102 mV). Only 3000–4500 mV is accepted.

Sources: [fr0styJS/g435-lightspeed-battery](https://github.com/fr0styJS/g435-lightspeed-battery), WirelessBattery PRs #72 / #93.

## Accuracy

Millivolts are exact. Percentage is a generic 3.7 V Li-ion estimate — Logitech publishes no G435 discharge table. A new voltage within ±2% of the displayed percent does not change the tray value.

## Behavior

- The Realtek path leaves bootloader mode after every read that successfully entered it. The exit is RAII, so a failed query cannot leave the dongle wedged (which freezes USB audio).
- Reads are rate-limited to once per **45 minutes** after a success, and once per **5 minutes** after a failure. A USB re-enumerate mid-read does not start another query.
- The first USB read waits about 20 seconds after launch. `WirelessBattery.exe --list` skips that wait and reads once (audio may mute for about a second on the Realtek receiver). `WirelessBattery.exe --dump` only enumerates HID collections and does not open the bridge.
- The cache is in memory only. A failed read keeps the last percent on screen as asleep. If the receiver itself disappears, the app keeps that value for 30 minutes (`graceSec`).

## Tests

The protocol helpers have a unit test that does not need HID hardware:

```bat
g++ -std=c++17 -O2 -Wall tests/g435_protocol_test.cpp -o build/g435_protocol_test.exe
build\g435_protocol_test.exe
```
